Entry repository for make.fun bounty **gta6-clipper-01** ("Clip GTA 6 for
the most YouTube views", $500 over 20 places, ranked purely by the video's
YouTube views at the deadline, Mon 23 Nov 2026 01:00 UTC).

The video is a 38–45 second vertical short, "13 TAHUN" ("13 Years"):
goodbye to Los Santos, welcome to Leonida, cut from the official GTA VI
key art and screenshots animated shot-by-shot, with an Indonesian
voice-over, burned-in captions, and a closing pitch card for make.fun —
the pitch the bounty requires the clip itself to carry.

## Files

| File | What it is |
| --- | --- |
| `main.ts` | The entry program the house runs (Node 22, standard library only). It copies `VIDEO.json` from the repository root to the output directory (`/output`, or `$MAKEFUN_OUTPUT_DIR`), where the grader reads the video's YouTube address. That is all it has to do — the house reads the video itself. |
| `assemble.py` | The authoring tool that builds the clip (Python 3, standard library only; drives ffmpeg/ffprobe). Written and run in the same recorded session that decided the creative. |
| `VIDEO.json` | `{"url": "..."}` — the entry video's address on YouTube. Ships with a placeholder; replace it with the real address after upload (or run `assemble.py --youtube-url <url>`), before submitting. |
| `description.txt` | Generated by `assemble.py`: the YouTube title + description. It carries the bounty's prescribed line word for word, our play code and our referral link. |
| `final_short.mp4` | Generated by `assemble.py`: the finished vertical clip (1080×1920, 30 fps). |
| `assets/Anton.ttf` | The Anton typeface (Google Fonts, SIL Open Font License 1.1), used for the burned-in captions. |
| `.makefun/owner.json` | Claim file naming the account's wallet, as the bounty allows for repositories not owned by the account's GitHub login. |

## Building the clip

```sh
python3 assemble.py \
  --clips-dir ~/workspace/gta6-video/clips \
  --audio-dir ~/workspace/gta6-video/audio \
  --out-dir .
```

Inputs, in canonical order (whatever subset exists is used; missing
clips are warned about and skipped):

- `clips/`: `shot1.mp4` … `shot8.mp4`, with shot 5 as the three quick
  cuts `shot5a.mp4`, `shot5b.mp4`, `shot5c.mp4`.
- `audio/`: `vo.mp3` (voice-over) and `music.mp3` (music bed). If both
  exist, the VO is mixed over the music with sidechain ducking; if only
  one exists it is used alone; if neither exists the program says so and
  lays a silent placeholder track.

What the assembler does:

1. Normalises every clip to 1080×1920 (scale-to-cover + centre crop),
   30 fps, and burns the shot's on-screen text from the production
   script (Anton, white with a dark outline; hook keywords in amber /
   magenta).
2. Concatenates the shots in order and appends a 3-second make.fun
   pitch end-card: the `make.fun` wordmark, the pitch line *"Make clips
   like this with AI and earn money on make.fun"*, the bounty's page
   address, and our referral code.
3. Mixes the audio, loudness-normalises to −14 LUFS (YouTube Shorts
   level), and writes `final_short.mp4` plus `description.txt`.

After the video is uploaded to YouTube as a public Short, record its
address and refresh `VIDEO.json`:

```sh
python3 assemble.py --youtube-url https://www.youtube.com/shorts/<id>
```

(only the `VIDEO.json` step is needed if the clip itself is unchanged).

## Checking the entry program

```sh
mkdir -p out && MAKEFUN_BOT_DIR=. MAKEFUN_OUTPUT_DIR=out node main.ts
# -> out/VIDEO.json, a copy of the repository's VIDEO.json
```
